# Backups and restoration
1. Keep this release ZIP in at least two owner-controlled locations. Commit the extracted repository to GitHub or another independent Git host. Tag each deployed release. Keep the checked-in geographic assets with their manifests. Use the source ZIP even if the original hosting account disappears.
2. Back up application data before migrations and at an interval matching your retention policy. Use the Supabase-supported CLI or pg_dump with a secure database connection. Include public application tables, voyage_private and sequences. Auth identities and verified email state are separate recovery dependencies. Follow the provider's current Auth migration guide to preserve UUIDs and credential state. A public-schema backup alone cannot restore private records linked to Auth. Record allowed redirect URLs, provider configuration, email settings, installed extensions and migration versions separately. Encrypt backups. Keep credentials outside Git.
3. Restore into a different, empty free staging project. Disable registrations and external email. Restore provider-compatible Auth identities and database roles first. Use either a complete schema-and-data restore or install numbered migrations and restore matching data-only exports in dependency order. Temporarily control the signup gate from the database owner console while restoring pre-existing identities, then close it again. Do not expose staging to public registrations.
4. Reapply access grants and verify policies, triggers, audit logs and sequences. Compare counts and foreign keys. Test one user across two devices and two different users in separate private sessions. Check that each sees only their own records and that an ordinary account cannot moderate. Verify no stale operator access migrated inadvertently.
5. Configure the new public project URL/key, deploy the frontend and test public/offline exploration before switching traffic. Reopen write features only after the owner completes the release gates. Revoke credentials of the previous hosting environment. Test provider-specific production recovery separately. The repository includes an isolated database snapshot/restore test.
